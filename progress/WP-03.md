## 1. The reduced-motion contract

`prefersReducedMotion()` reads `matchMedia('(prefers-reduced-motion: reduce)')`
**live on every call**. Nothing is cached at boot, because a user can flip the OS
setting with the page open.

`initMotion()` sets or removes `.no-motion` on `<html>` and re-runs that decision
on the media query's `change` event. `classList` is only touched when the state
actually changes (section 12.1). The deprecated `addListener` path is kept for
old Safari.

What reduced motion changes, concretely:

| Surface | Motion on | Reduced motion |
|---|---|---|
| Scroll driver | One Lenis instance, wired to ScrollTrigger | Lenis is **never constructed**. A passive native `scroll` listener marks a dirty flag. |
| `getLenis()` | The instance | `null` |
| `scrollToTarget` | `lenis.scrollTo(target, { offset, duration: 1.1 })` | Native jump to `rect.top + scrollY + offset`, `behavior: 'auto'`, which is what `scroll-margin-top: 80px` already assumes |
| `ScrollState` broadcast | identical | identical |
| Parallax | runs at and above 901px | not started, and any transform already written is cleared |
| Reveals | IntersectionObserver plus CSS transition | `.is-revealed` added **synchronously inside `reveal()`**, then return |
| `will-change` | added on fire, removed on `transitionend` (opacity only) or backstop | never added at all |

**Why no element can sit at `opacity: 0` under reduced motion (section 19).**
This is structural, not probabilistic. There are exactly three points in
`observe.ts` where the settled class could be deferred, and every one of them
re-reads `prefersReducedMotion()` immediately before deferring:

1. `reveal()` entry: reduced motion adds `.is-revealed` and returns before an
   observer is ever created.
2. `settle()`, reached from the observer callback: re-checks, because the user
   may have turned reduced motion on between registration and intersection.
3. the inside of the per-element stagger `setTimeout` in `settle()`: re-checks
   again before it applies the hint and the class.

There is no fourth path. `revealGroup` calls `reveal` and additionally forces the
stagger step to 0 under reduced motion, so a group settles in one frame rather
than over N frames. Belt and braces, the WP-02 CSS rule `.no-motion .reveal`
settles the initial state anyway, so even an element that was never handed to
`reveal()` is visible.

`observeOnce` is deliberately **independent** of reduced motion. It is a loading
trigger (WP-07 lazily imports 3Dmol at 1.5 viewport heights), not an animation,
and gating it would break the structure section for reduced-motion users.

## 2. The scroll spine

One Lenis instance, created only in `installLenis()` in `core/scroll.ts`. The
wiring is exactly section 6.3:

```
lenis.on('scroll', ScrollTrigger.update);
gsap.ticker.add((time) => lenis.raf(time * 1000));
gsap.ticker.lagSmoothing(0);
```

`ScrollTrigger.scrollerProxy()` is **not** used and must not be used anywhere.
Lenis drives native `window.scrollY`, so it is not a virtual scroller;
`scrollerProxy` is for transform-based scrollers such as Locomotive v4 and using
it here is the direct cause of the pin-misplacement class of bug that section 6.4
exists to prevent. `gsap.registerPlugin(ScrollTrigger)` happens here and nowhere
else.

**One broadcast, two drivers.** Both drivers do the same trivial thing: set
`dirty = true`. A single rAF loop consumes the flag, reads `window.scrollY` once,
computes `velocity` as the raw frame delta (signed px per frame) and `progress`
as `y / (docHeight - viewportHeight)` clamped to 0..1, then fans out to every
subscriber. Subscribers cannot tell which driver is running, which is the
requirement in section 6.3.

- `onScroll(fn)` returns an unsubscribe closure that deletes the subscriber from
  the `Set`.
- The `ScrollState` object is allocated once and reused, so the loop allocates
  nothing per frame.
- The loop early-outs when nothing moved, nothing is dirty, and the last reported
  velocity was already 0. That guarantees exactly one final frame reporting
  `velocity: 0` when scrolling stops, then silence.
- `onScroll` is safe to call before `initScroll()`; it starts the loop lazily so
  the core is testable standalone.

**No layout reads in the loop.** `innerWidth`, `innerHeight` and the document
scroll height live in one cached `view` object, refreshed only by a rAF-throttled
`resize` / `orientationchange` handler. The only per-frame read is
`window.scrollY`.

## 3. Parallax caching strategy (section 6.5)

Three depths. `near` is factor 1.00, carries **no attribute**, and is never
written to at all, which is what makes a factor of 1.00 genuinely zero transform
rather than a rounded-to-zero one. `mid` is 0.94, `far` is 0.86. An unrecognised
`data-depth` value is treated as `near`: no cache entry, no transform.

```
translateY = clamp((1 - factor) * (scrollY - elementTop), -80, 80)
```

The clamp is mandatory and is enforced at +/- 80px. Without it an element far
down a long page accumulates hundreds of pixels of transform and tears out of its
layout. The harness verifies elements near the bottom of a tall page pin at
exactly -80 / +80.

Caching:

- `measure()` is the ONE layout read pass. It runs on start, on the rAF-throttled
  resize, on a live reduced-motion change, and once more when `document.fonts.ready`
  resolves (late fonts move elements and invalidate the cached tops).
- Each element's document-absolute top is cached in a flat array of
  `{ el, top, factor, last }`. `getBoundingClientRect().top + scrollY` is used
  rather than `offsetTop` because `offsetTop` is relative to the nearest
  positioned ancestor and a parallax element can easily sit inside one. Before
  measuring, any transform this module wrote is cleared so the cached top is the
  untransformed layout position, then restored.
- The scroll loop does arithmetic only: no reads, and **one** `style.transform`
  write per element per scroll event. A write is skipped entirely when the new
  value differs from `last` by under 0.01px, because sub-pixel churn is invisible
  and still costs a compositor update.
- `translate3d(0, Npx, 0)` is used so the element stays on its own layer.

Parallax is skipped entirely under reduced motion and below 901px, and
`stopParallax()` unsubscribes from the broadcast and clears every transform it
wrote, so a resize down past the gate leaves no residue.

## 4. will-change lifecycle (section 6.6)

Both documented failure modes are handled:

1. **Double fire.** Transitioning `transform` and `opacity` emits two
   `transitionend` events. The handler returns immediately unless
   `e.propertyName === 'opacity'`, and a `cleared` flag makes the teardown
   idempotent regardless.
2. **Never fires.** Under reduced motion the duration is zero and `transitionend`
   may never arrive. So the hint is never added in no-motion mode, **and** a
   `setTimeout` backstop at `DUR.reveal * 1000 + delay + 200ms` removes it
   regardless of whether the event ever came. The backstop also clears the
   listener, so nothing is left attached.

The per-element stagger is applied as the element's own delay before the class
flip, so each element's backstop is computed against its own delay rather than a
group maximum. The harness asserts that after a full scroll sweep, zero revealed
elements still carry an inline `will-change`.

## 5. Observers

One `IntersectionObserver` per distinct `rootMargin`, held in a
`Map<string, SharedObserver>`, never one per element. Reveals all share
`'0px 0px -10% 0px'`. `observeOnce` creates (or reuses) one observer for whatever
margin the caller asks for, so WP-07's `'0px 0px 150% 0px'` costs one observer for
any number of lazy targets.

## 6. Harness

`qa/motion-harness.html`. No section code, no copy, no project stylesheet: the
reveal primitives are inlined so the file stands alone.

```
npx vite
open http://localhost:<port>/qa/motion-harness.html
open http://localhost:<port>/qa/motion-harness.html?reduce=1
```

`?reduce=1` patches `matchMedia` before the modules load so the native-driver
path can be exercised without changing OS settings. The fixed panel shows the
live driver, the `.no-motion` state, `y` / `velocity` / `progress`, the broadcast
count, the console error count, and a running audit of how many `.reveal`
elements are at `opacity: 0`, printing FAIL if that is ever non-zero while
reduced motion is on.

Verified with Playwright at 1440x900, full scroll sweep, both drivers:

- console errors 0, page errors 0, unhandled rejections 0
- driver `lenis` / `no-motion: false` normally; `native` / `no-motion: true` under
  reduced motion, with `getLenis()` returning null
- 6 of 6 reveals settled, 0 elements at opacity 0, 0 leftover `will-change`
- parallax: `mid` and `far` transformed and clamped at 80px, `near` transform
  `none` in both runs; all transforms `none` under reduced motion
- `scrollToTarget('#target')` lands the target 80px from the viewport top on both
  the Lenis path and the native path
- `observeOnce` fired exactly once

## 7. Notes for other work packages

- Nothing outside `core/scroll.ts` may construct Lenis, attach a raw `scroll`
  listener, call `ScrollTrigger.scrollerProxy`, or configure ScrollTrigger's
  scroller. Subscribe to `onScroll` instead.
- `gsap.matchMedia()` belongs to WP-10 in `main.ts` and is deliberately absent
  here. `MQ_DESKTOP_MOTION` is exported for it to use verbatim.
- `main.ts` should call `initMotion()` then `initScroll()`.
- WP-02: the four `--ez-*` tokens in `tokens.css` are the CSS mirror of the
  `CURVES` constant at the top of `core/motion.ts`. Values are
  `--ez-out-expo: cubic-bezier(0.19, 1, 0.22, 1)`,
  `--ez-out-quart: cubic-bezier(0.165, 0.84, 0.44, 1)`,
  `--ez-in-out: cubic-bezier(0.77, 0, 0.175, 1)`, `--ez-linear: linear`. Both
  sides derive from one set of numbers; changing one without the other is the
  only way they can drift.
- Lenis's optional stylesheet is not imported, because the stylesheet import
  order in `main.ts` is fixed and owned by WP-01 and this build needs none of it
  (no `scroll-behavior: smooth` is set anywhere, which is the one rule that
  matters). If a later package adds `scroll-behavior: smooth`, remove it rather
  than adding the Lenis CSS.

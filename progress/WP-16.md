## How to run

Every script is plain ESM, runs under plain `node`, takes an optional base URL
as its first argument, and defaults to `http://localhost:4173`, the vite preview
port. Start the preview server first for the four browser scripts:

```
npm run build
npm run preview
```

Then, from the repository root:

```
node qa/copylint.mjs                     # static source scan, no server needed
node qa/links.mjs                        # or: node qa/links.mjs http://localhost:5173
node qa/a11y.mjs
node qa/perf.mjs
node qa/shots.mjs
```

### Exit codes

| Code | Meaning |
|---|---|
| 0 | Pass. |
| 1 | A real violation. This is the build-failing case. |
| 2 | Not ready: the preview server is not up, the page returned non-200, the page has zero mounted sections, or a required input file is missing. Printed as a plain sentence with the fix, never a stack trace. |
| 3 | The harness itself threw. A harness bug, not a site failure. |

Exit code 2 is deliberately distinct from 1 so that a run before Wave 3 lands is
legible as "not yet" rather than "broken".

### Browser binary

`playwright` is the section 3.3 devDependency installed by WP-01. The Chromium
binary was fetched once with `npx playwright install chromium`. No dependency
was added and `package.json` was not touched.

## What each script gates

### `qa/copylint.mjs` (spec section 16.5, overrides A1 and A4)

Two passes, no browser.

**Pass 1** reads `src/content/copy.ts` and applies the ten literal regexes from
section 16.5 verbatim, plus an eleventh rule that section 16.5 describes but does
not express as a flat regex: every occurrence of `100%` must be followed within
60 characters by the string `curated`. The en dash rule requires a space on both
sides, so `2010-2020` style numeral ranges pass and a spaced en dash used as a
connector fails. Verified against a synthetic fixture: all eleven rules fire, and
the numeral range does not.

**Pass 2** walks all of `src/` plus `index.html` and fails on the em dash U+2014,
any emoji, the two banned brand strings and their lowercase form, and any email
address pattern. Those are overrides A1 and A4, and they are hard gates.

Every hit reports file, line number, the matched text and the offending source
line.

The banned brand needles are assembled from character codes inside the linter, so
the linter does not itself contain the literals it hunts for.

### `qa/perf.mjs` (spec section 16.1, budgets section 12)

Chromium with CPU throttled 6x via CDP `Emulation.setCPUThrottlingRate`. Loads
the page, lets the boot settle for 2.5s, then sweeps scroll from top to bottom
over exactly 8 seconds driven by an in-page rAF loop.

Prints median frame, p95 frame, janked-frame percentage, every long task with its
start and duration, and total script time.

Fails when any section 12 budget is missed:
- median frame not under 12ms,
- janked frames (over 20ms) not under 2%,
- any long task over 200ms that is not one of the two permitted one-time inits.

### `qa/shots.mjs` (spec section 16.2)

At 375x812, 900x1200 and 1440x900: scrolls the entire page in steps first, so
every IntersectionObserver reveal has fired and any lazy media has loaded, waits
for network idle, then captures one full-page shot plus one shot per section,
numbered in document order.

Output goes to `qa/shots/<width>x<height>/`, which is already in `.gitignore`.
The directory is wiped at the start of every run.

### `qa/a11y.mjs` (spec sections 16.3, 13, 16.6)

Five checks.

1. **axe-core** injected from the `axe-core` devDependency and run against the
   page. Any violation fails.
2. **Contrast against the COMPUTED background, not the token table.** Every text
   node is walked, its parent element's computed `color` is read, and the backdrop
   is found by climbing ancestors and compositing every translucent layer until an
   opaque one is reached. Translucent foreground colors are composited over that
   backdrop before the ratio is taken. Threshold is 4.5:1, or 3:1 for large text
   (24px, or 18.66px at weight 700 or heavier). Run at all three viewports.
   Sanity-checked against the spec's own recorded measurement: `#9AA3AC` on
   `--paper` comes back as 2.43:1, matching section 13.3 exactly.
3. **Focus order.** Tabs through the page up to 250 stops, recording and printing
   the full order. Fails on a focus trap (the same element focused across three
   consecutive Tab presses, or no cycle after 250 stops) and on any focused
   element that is invisible, zero-sized, or off-screen after focus.
4. **Reduced motion**, section 13.1. Reloads in a context with
   `reducedMotion: 'reduce'` and asserts: no element remains at opacity 0, the
   How-it-works content is reachable (present, non-zero height, real text, inside
   the scrollable document), Lenis is not installed, and zero ScrollTrigger pins
   or scrubs are active.
5. **Console gate**, section 16.6.

### `qa/links.mjs` (spec section 16.4, overrides A3 and A4)

Scrolls once so deferred markup has mounted, then collects every `[href]` on the
page and asserts each resolves:
- an internal `#id` anchor must match a real element id (or an `a[name]`),
- an external http/https link must answer 200 (HEAD, retried with GET when HEAD
  is refused with 405, 403 or 501; results are deduplicated),
- a same-origin path must answer 200.

This is the check that catches an anchor pointing at a renamed section id.

It also enforces override A3: exactly the eight shells `hero, problem, how,
outputs, validation, structure, traction, contact`, no more, no fewer, no element
with id `team`, and no `#team` anchor. And override A4: no `mailto:` link and no
email address in the rendered text.

### Section 16.6 in all four browser scripts

`perf.mjs`, `shots.mjs`, `a11y.mjs` and `links.mjs` each attach a `console`
listener for `error`-type messages, a `pageerror` listener, and an
`unhandledrejection` listener installed via `addInitScript` so it is armed before
any page script runs. Any of the three failing the run is a hard gate, not a
warning. `a11y.mjs` and `shots.mjs` apply the gate per viewport and, for
`a11y.mjs`, again to the reduced-motion pass.

## The perf measurement approach, recorded

Section 16.1 asks explicitly for the chosen approach to be recorded.

**Frame deltas: an injected requestAnimationFrame loop.** There is no
frame-timing entry type in the Performance API, so a rAF loop is installed via
`addInitScript` before any document script runs and pushes the delta between
consecutive rAF timestamps into an array on `window`. The array is read out after
the sweep and only the frames whose timestamps fall inside the sweep window count
against the budget. The stated alternative, CDP `Tracing.start`, was **not**
used: it is more accurate and considerably more work, and section 16.1 accepts
either provided the choice is recorded.

**Long tasks: a separate PerformanceObserver on `{ type: 'longtask' }`**, which
does exist, with `buffered: true` so tasks that ran before the observer attached
are still captured. If the observer fails to attach at all, that is itself a
failure rather than a silently empty list.

**Total script time: CDP `Performance.getMetrics`**, reading `ScriptDuration`.
`TaskDuration` is printed alongside it for context.

**One flag choice that materially shapes the numbers.** Chromium is launched with
`--disable-gpu-vsync` and `--disable-frame-rate-limit` (plus the background
throttling flags). Without them, rAF is clamped to the display refresh rate and
every frame delta reads as roughly 16.7ms, which would make the section 12 budget
of "median frame under 12ms" unreachable for any page at all, including an empty
one. With vsync off, a frame delta measures main-thread work rather than the
compositor clock, which is what the budget is actually about. This is printed in
the script's own header output on every run, so the number is never read without
the condition that produced it.

### The two permitted long-task exclusions

Section 12 excludes "the one-time seqviz mount and the one-time 3Dmol init" from
the zero-long-tasks-over-200ms budget. Both are identified by **position** and
**duration**, each may be excluded **at most once**, and both are printed in full
with the reason. Nothing is ever excluded silently.

- **seqviz mount.** Candidates are long tasks starting at or before the sweep
  start plus a 1500ms grace. Section 8.6 mounts seqviz in a `requestIdleCallback`
  after first paint, and an idle callback has no guaranteed wall-clock time, so a
  window rather than a point is the only honest identification.
- **3Dmol init.** The sweep records, in-page, the exact moment the `#structure`
  section first comes within 1.5 viewport heights, which is precisely when
  section 9.5 triggers the dynamic import. Candidates are long tasks starting
  within 3000ms of that mark. If the structure section never came within that
  distance during the sweep, no window existed, no exclusion is applied, and the
  script says so in its output.

When two candidates sit in one window the longest is the one excluded, on the
grounds that the genuine one-time init is the expensive one. Every other long
task over 200ms is a hard failure with its duration and start time named.

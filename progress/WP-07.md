## 2. The module, `src/fx/viewer3d.ts`

Contract C9 is exact:

```ts
export function mountViewer3d(el: HTMLElement): Promise<{ setZoom(p: number): void; destroy(): void } | null>;
```

Behaviour worth knowing if you are WP-09f or WP-10:

- **The promise settles immediately.** It resolves `null` when the still was
  rendered, and otherwise resolves the handle straight away, before 3Dmol has
  been imported. The import and first render happen later, on approach. Any
  `setZoom` call made before then is buffered and applied the moment the viewer
  exists. An implementation that only resolved on approach would have left
  WP-09f awaiting a promise that never settles until the user scrolls.
- **No ScrollTrigger is created here.** `setZoom(p)` maps `0..1` to camera zoom
  and WP-10 drives it from the single `matchMedia` block (spec section 6.4).
- **DOM.** The module adds `.fx-viewer3d` to the element it is given and appends
  either `div.fx-viewer3d__stage` (which 3Dmol fills with its canvas) or
  `img.fx-viewer3d__still`. It appends nothing else and queries nothing outside
  its own element, so the attribution line (`structure.pdbcredit`, WP-04's
  string, rendered by WP-09f) cannot collide with it.

### Palette

Hex literals, because 3Dmol runs in WebGL and cannot resolve CSS custom
properties. They are kept in sync with `tokens.css` by hand and the file says so
in a comment.

| `atom.ss` | Hex | Token |
|---|---|---|
| `h` (helix) | `#1F6B4A` | `--accent` |
| `s` (sheet) | `#2E6F95` | `--feat-promoter` |
| `c` (coil) | `#656E77` | `--ink-faint` |
| background | `#F2F0EC` | `--paper-sunk` |

3Dmol sets `atom.ss` to the single characters `h`, `s`, `c`, never
`helix`/`sheet`/`coil`. The `colorfunc` keys on the single characters and falls
back to the coil grey. No spectrum, no rainbow, no coloured lights, default
lighting, `antialias: true`, cartoon with `thickness: 0.4` and `arrows: true`,
then `zoomTo()` and `render()`.

Confirmed from rendered pixels, not from the source: the eight most common
colours in the live canvas are the paper-sunk background and shaded variants of
the blue sheet and grey coil. No saturated or out-of-palette hue appears.

### Motion, spec section 7.6

- Auto-rotation is `viewer.rotate(0.2, 'y')` once per animation frame. `rotate`
  re-renders, so there is no second `render()` per frame.
- Drag is 3Dmol's own handler. A `pointerdown` on the stage stops the loop, and
  `pointerup`/`pointercancel` on `window` (so a release outside the canvas still
  counts) sets a 4,000 ms resume time.
- Under reduced motion the loop is never started, so nothing auto-rotates, and
  the viewer stays draggable because 3Dmol owns that interaction.
- The rAF loop stops when the element leaves the viewport (its own
  `IntersectionObserver`), when the tab is hidden, and on `destroy()`.
- `setZoom(p)` is absolute, not accumulating: the target factor is
  `0.78 + p * (1.55 - 0.78)` relative to the `zoomTo()` fit, and the module
  applies `target / alreadyApplied` so repeated scrub calls cannot drift.

### Lazy loading, spec sections 9.5 and 12

One `observeOnce(el, load, '150% 0px 150% 0px')` from `core/observe.ts`. The
margin is 1.5 viewport heights above and below, because the section can be
approached from either direction. `await import('3dmol')` happens inside that
callback and nowhere else.

### Fallback, spec section 9.4

`!WebGLRenderingContext` (or a context probe that fails) or
`window.innerWidth < 720` renders the still and returns `null`, and 3Dmol is
never requested. A failed import or a failed structure fetch also swaps in the
still rather than leaving a blank box, with one `console.warn` (a warning, not
an error, so the zero-console-errors gate still holds).

### Accessibility, spec section 13.2

The stage carries `role="img"` plus an `aria-label` describing the barrel, the
central helix and the colour coding in words. The still carries the same
description as its `alt`. Neither is empty, neither is a filename.

These two strings live in `viewer3d.ts` rather than `copy.ts`, because the
frozen `copy.structure` shape in contract C3 has no alt key and `copy.ts`
belongs to WP-04. Noted as a cross-WP line in `PROGRESS.md`.

### Layout stability

`.fx-viewer3d` reserves `aspect-ratio: 4 / 3` and the still carries explicit
`width="1200" height="900"`, so neither the canvas nor the image can shift
layout. The still is `loading="eager"`, because the structure section is
measured by a scroll scrub and a late image inside a measured section produces
stale triggers (spec section 7.3).

## 3. Still regeneration: the exact camera

Regenerate whenever the palette in `tokens.css` or the structure changes. The
camera is fully determined by the recipe below, which is why no view matrix is
quoted: 3Dmol's `createViewer` keeps no global registry to read `getView()` back
from, and the recipe reproduces the frame exactly.

| Parameter | Value |
|---|---|
| Structure | `public/data/structures/gfp.pdb` (RCSB 1EMA), unmodified |
| Viewer config | `{ backgroundColor: '#F2F0EC', antialias: true }` |
| Style | `cartoon` with the `SS_COLORS` colorfunc, `thickness: 0.4`, `arrows: true` |
| Orientation | The default `viewer.zoomTo()` orientation. **No rotation is applied.** Captured under `reducedMotion: 'reduce'` so the 0.2 deg/frame auto-rotation never starts. |
| Zoom | `setZoom(0.5)`, which is `zoomTo()` fit multiplied by `0.78 + 0.5 * (1.55 - 0.78) = 1.165`. The midpoint of the scrub range is used because a phone never scrubs, so this is the representative frame rather than the widest one. |
| Stage size | 1200 x 900 CSS px, `deviceScaleFactor: 2`, so the WebGL canvas is 2400 x 1800 |
| Capture | Chromium via the installed `playwright` package, `drawImage` of the live canvas onto a 1200 x 900 2D canvas pre-filled with `#F2F0EC`, then `toDataURL('image/webp', 0.92)` |
| Output | `public/data/structures/gfp-still.webp`, 1200 x 900, 66,894 bytes |

The generator, the harness page and the two verification scripts were temporary
files at the repository root (none of them WP-07 property) and were deleted
after the run. Copies are in the session scratchpad at
`.../scratchpad/wp07-{harness.html,vite.config.mjs,still.mjs,check.mjs,motion.mjs}`.
Reproducing them is mechanical: a root HTML page that imports
`tokens.css`, `sections.css` and `mountViewer3d`, mounted into a 1200px box
between two 400vh spacers, built with a throwaway Vite config whose
`rollupOptions.input` is that page, then served statically to Chromium.

## 5. Notes for other work packages

- **WP-09f.** `await mountViewer3d(shell)` resolves immediately. `null` means
  the still is showing, so skip anything that assumes a live canvas. Keep the
  `structure.pdbcredit` line as a sibling of the viewer element, not inside it:
  everything inside is managed by this module.
- **WP-10.** Call `handle.setZoom(progress)` from the scrub. Do not create a
  ScrollTrigger in `viewer3d.ts`, and do not call `setZoom` on a `null` handle.
- **WP-15.** The 3Dmol chunk is roughly 170 KB gzipped and is excluded from the
  initial budget by spec section 12. Verify it is still a separate chunk on the
  assembled build, and that a 390px-wide run never requests it.
- If `--accent`, `--feat-promoter`, `--ink-faint` or `--paper-sunk` change in
  `tokens.css`, update `SS_COLORS` / `BACKGROUND` in `viewer3d.ts` and
  regenerate the still with the section 3 recipe.

## 1. `public/data/demo-plasmid.json` is a PLACEHOLDER

Per BUILD_CONTRACT override A6 Q2, no real construct export is available, so
this ships the placeholder shape from spec section 8.3 and is loud about it in
three places at once:

1. A literal `"_TODO"` key inside the object. JSON has no comment syntax, which
   is exactly why the spec mandates a key: a `//` line would make
   `fetch().json()` throw. The value spells out that the payload is synthetic
   demonstration data, that it is not an export from any real design run, and
   that the whole file plus the key is to be replaced.
2. A console WARNING on every page load while the key is present, from
   `loadPlasmidPayload()`. Not an error: spec section 16.6 makes console errors
   a hard build gate, and a known placeholder must not fail that gate.
3. A line under `## Blocked` in `PROGRESS.md`.

**Nothing in the payload asserts that it came from a real product run.** The
name is `pCON-DEMO-01`, the feature names are the ordinary published names of
standard parts (T7 promoter, GFP, T7 terminator, AmpR, ori, rrnB T1
terminator, KanR), and no field claims provenance.

The payload is otherwise structurally valid and visually plausible:

| Property | Value |
|---|---|
| `name` | `pCON-DEMO-01` |
| `length` | 5412, and `seq.length` is exactly 5412 |
| `seq` | real DNA characters, A C G and T only |
| `annotations` | 7 entries, each with `name`, `start`, `end`, `direction`, `type` |

Coordinates are **0 based, start inclusive, end exclusive**, which is what
seqviz consumes, and that convention is stated inside the `_TODO` value so the

- the three coding features are whole multiples of three, start `ATG`, end
  `TAA`, and contain no internal stop codon
- the T7 promoter window carries the real 20 bp T7 consensus and the T7
  terminator window carries the real terminator sequence

## 2. Feature colors

seqviz renders through React to SVG and cannot resolve CSS custom properties,
so `FEATURE_COLORS` in `src/fx/plasmid.ts` holds hex literals. The comment
above it names `src/styles/tokens.css` as the source of truth those literals
must stay in sync with, because nothing in the build can detect the drift.

```
promoter    #2E6F95   --feat-promoter
cds         #1F6B4A   --feat-cds
marker      #8A5E12   --feat-marker
origin      #6B4A7A   --feat-origin
terminator  #5C6570   --feat-terminator
```

The hexes reach seqviz twice: as a `color` on each annotation, which is
authoritative, and as the `colors` array, which is seqviz's fallback pool for
anything that arrives uncolored. The Playwright run reads the `fill` off every
rendered arc and asserts all seven are one of these five values.

## 3. The name-pattern to type mapping function

`featureType(annotation)` resolves a feature's type. An explicit `type` on the
annotation always wins, so today's payload never touches the pattern table.
The table exists because spec section 8.3 says a real export may not carry
`type`, and when that export arrives it has to drop in without a code change.

Patterns are ordered most specific first, matched case-insensitively against
the feature name, and the first hit wins. Anything unmatched falls back to
`terminator`, the neutral grey, so an unknown feature is never miscolored as a
confident claim.

| Order | Pattern intent | Examples that hit it | Type |
|---|---|---|---|
| 1 | the word terminator, or `term` | `T7 terminator`, `rrnB T1 term` | terminator |
| 2 | polyadenylation signals | `polyA`, `poly-A signal` | terminator |
| 3 | origins of replication | `ori`, `origin`, `ColE1`, `p15A`, `pUC`, `pMB1`, `f1`, `SV40 ori` | origin |
| 4 | replication proteins and transfer origins | `rep`, `repA`, `oriT` | origin |
| 5 | resistance genes | `AmpR`, `KanR`, `CmR`, `cat`, `TetR`, `SpecR`, `bla`, `neo`, `hyg`, `puro`, `bsd`, `gent` | marker |
| 6 | the words resistance, selection marker, marker | `Amp resistance` | marker |
| 7 | auxotrophic markers | `LEU2`, `URA3`, `HIS3`, `TRP1`, `LYS2` | marker |
| 8 | the word promoter, including the common misspelling | `T7 promoter`, `CMV promotor` | promoter |
| 9 | bare promoter names | `T7`, `T3`, `SP6`, `lac`, `tac`, `trc`, `araBAD`, `tetO`, `CMV`, `EF1a`, `SV40`, `PGK`, `UBC`, `CAG`, `GAL1`, `ADH1`, `TEF1` | promoter |
| 10 | other upstream regulatory elements | `RBS`, `Shine-Dalgarno`, `Kozak`, `operator`, `enhancer`, `UTR`, `IRES`, `WPRE`, `TATA` | promoter |
| 11 | the words CDS, ORF, gene, coding, protein, peptide | `GFP CDS`, `AmpR gene` | cds |
| 12 | reporter genes | `GFP`, `EGFP`, `YFP`, `mCherry`, `DsRed`, `RFP`, `BFP`, `CFP`, `mScarlet`, `luciferase`, `lacZ` | cds |
| 13 | tags, fusions and linkers | `His6`, `6xHis`, `FLAG`, `myc`, `HA tag`, `Strep-tag`, `GST`, `MBP`, `SUMO`, `TEV`, `linker`, `signal peptide` | cds |
| fallback | no pattern matched | anything else | terminator |

Two ordering decisions worth knowing before editing the table:

- Terminators are tested first. `rrnB T1 terminator` contains `T1`, and a
  looser promoter rule further down would otherwise claim it.
- Resistance genes are tested before promoter names. `TetR` is a repressor
  protein and a selection context far more often than it is the `tetO`
  operator, and `AmpR` must never fall through to the `cds` reporter rule.

## 4. The draw-on-load animation

Post-processing of the rendered SVG. seqviz is never patched, and no SVG
attribute is tweened by GSAP. Every visual change is a CSS transition driven by
a class toggle, per spec section 6.2, with the per element stagger carried as
inline custom properties (`--fx-delay`, `--fx-dur`, `--fx-rot`).

**Backbone.** WP-06 appends its own `<circle>` into the rendered SVG. seqviz
builds the circular index line from two rotated half-arcs and exposes no stable
selector for a single backbone element, so `getTotalLength()` on "the backbone"
has nothing reliable to grab. The overlay is measured instead: the index lines
are unioned in screen space, where every transform on the way down has already
been applied, and one box is mapped back into the SVG's own user space through
`svg.getScreenCTM().inverse()`. That yields the centre and radius from geometry
that is visible rather than from a third party's internal DOM shape.
`stroke-dasharray` and `stroke-dashoffset` are set to the circumference, the
offset transitions to 0 over 1.4s with `--ez-out-expo`, and the overlay is then
removed, revealing seqviz's real ring underneath. seqviz's ring, ticks and tick
labels are held at opacity 0 for the duration of the draw so the two are never
visible at once.

**Feature arcs.** opacity 0 and `scale(0.96)` about the circle centre,
transitioning to opacity 1 and `scale(1)` with a 90ms stagger in genomic order.
The arcs are sorted by `start` before the stagger is assigned, because seqviz
emits them in row-packing order, not genomic order.

One trap here, recorded because it is not obvious: seqviz positions each arc
group with a `transform="rotate(deg, cx, cy)"` **presentation attribute**, and
any CSS `transform` outranks a presentation attribute. Setting `scale(0.96)` in
CSS would therefore have thrown away the rotation and collapsed every arc to
zero degrees. The rotation is parsed out of the attribute, restated as
`--fx-rot`, and the CSS writes `rotate(var(--fx-rot)) scale(...)` with
`transform-box: view-box` and `transform-origin` pinned to the same centre.
The Playwright run proves the restatement is exact by comparing every arc's
rendered box against the un-animated reduced-motion render: **max delta 0px**.
If the rotation cannot be parsed, the arc animates opacity only and never
receives a transform, so a future seqviz format change degrades to a fade
rather than to a scrambled map.

The settled classes are deliberately **not** removed at the end of the
timeline. They hold the CSS transform the arcs animated into; dropping them
would hand the arcs back to the attribute in a single frame, and any rounding
difference between the two would read as a jump.

**Labels.** opacity 0 to 1, 40ms stagger, starting after the arcs finish. The
target is each direct `<g>` child of `.la-vz-circular-labels`, which is the
only node in that subtree React does not pass a `style` prop to, so an inline
custom property set there survives seqviz's own hover re-renders.

**Timing**, relative to `m`, the moment the arcs exist in the DOM:

| Beat | Desktop |
|---|---|
| backbone draw | m+0.00s, 1400ms, `--ez-out-expo` |
| feature arcs | m+0.70s, 90ms stagger, 600ms each |
| feature labels | m+1.50s, 40ms stagger, 400ms each |

Total on the shipped payload is 2060ms. **On mobile (viewport at or below
900px) the animation still runs but every number is scaled by
`1600 / total`**, so the whole sequence lands in 1.6s. Measured at 375px:
1724ms wall clock from mount to fully settled, which is the 1.6s timeline plus
the settle poll's own interval.

**Reduced motion.** `mountPlasmid` returns before a single animation class or
custom property is written, so the map renders fully drawn with no draw
animation. This is structural, not probabilistic: the `--armed` class is the
only thing in the module that sets opacity 0, and it has exactly one call site,
guarded by `prefersReducedMotion()`. The `sections.css` block adds two
independent backstops (`.no-motion` and a `prefers-reduced-motion` media
query). Verified: 0 elements at opacity 0, and the map is settled 7ms after
mount.

The tooltip is the one element that would otherwise sit at opacity 0 forever,
so it **lives out of the DOM while it is not showing** and is appended on
demand. Spec section 19 and the section 16.3 sweep both assert that no element
is ever left at opacity 0, and a permanently present hidden tooltip is exactly
the element that quietly breaks that.

## 5. Interaction, spec section 8.5

- Hovering a feature arc applies `filter: brightness(0.94)` and shows a small
  mono tooltip carrying name, coordinates and strand, for example
  `T7 promoter  12..32  +`.
- No click behaviour. This is not a product surface.
- On touch and pen, hover becomes tap-to-show. A second tap on the same arc
  closes it, and a tap anywhere else dismisses it. The dismissal listener is
  registered in the capture phase on `document` so it fires whatever is
  underneath.
- The hover class is attached during the interaction pass, not the animation
  pass, so hover still works under reduced motion.

## 6. Performance, spec section 8.6

- The mount waits for a double `requestAnimationFrame`, then
  `requestIdleCallback` with a 1200ms timeout, falling back to
  `setTimeout(0)` on Safari, which has no idle callback. The hero text is
  therefore readable before the map appears.
- The container is a reserved `aspect-ratio: 1` box in the `sections.css`
  block, plus `contain: layout`. **Measured CLS was exactly 0.00 in all three
  runs.**
- The payload fetch is memoised, so the hero map and the miniature in the
  How-it-works section share one request.
- `mountPlasmid` is idempotent per element through a `WeakSet`, so a double
  call cannot produce two React roots on one node.

## 7. Accessibility, spec section 13.2

The rendered SVG gets `role="img"` and an `aria-label` that describes the
construct and its features in words, not a filename:

> Circular map of the construct pCON-DEMO-01, 5412 base pairs, with 7
> annotated features. T7 promoter, a promoter, at base 12 to 32 on the forward
> strand. GFP, a cds, at base 45 to 762 on the forward strand. ...

Direction is spoken as "forward strand" and "reverse strand" rather than as a
sign, and the type words come from the same `featureType()` the colors come
from, so the spoken label and the visual can never disagree.

## 8. Notes for other work packages

- **WP-09a (hero):** put `class="fx-plasmid"` on the map container **in the
  markup**, before `mountPlasmid` runs. That class is what reserves the
  aspect-ratio box, and the CLS budget is exactly 0.00. `mountPlasmid` adds the
  class defensively too, but by then the mount has already happened. Call it as
  `void mountPlasmid(el)`; it resolves when the animation has been started, not
  when it has finished, and it never rejects on a missing payload.
- **WP-09c (how it works):** the miniature is `mountPlasmid(el, { mini: true })`,
  which drops the index row and caps the box at 320px.
- **WP-02:** if a `--feat-*` value in `tokens.css` ever changes, change the
  matching hex literal in `FEATURE_COLORS` in the same edit. Nothing in the
  build detects the drift.
- **WP-15:** seqviz plus React is the single largest item in the bundle and is
  above the fold, so it cannot be deferred. The mount is deferred instead.
- Nothing outside this module may style a `la-vz-*` selector. Every rule in the
  WP-06 block that touches one is scoped by a `.fx-plasmid` state class.

## 1. The accessibility approach, and why this one

The obvious implementation of a split is to replace the element's text with a
list of spans. Two things break at once when you do that:

1. A per glyph split is announced one letter at a time. A screen reader user
   hears "D, e, s, i, g, n" instead of "Design".
2. A per word split drops the whitespace, so selecting the heading and copying
   it yields `Designisthebottleneck.`

There are three common fixes and only one of them solves both.

| Approach | Screen reader | Clipboard | Verdict |
|---|---|---|---|
| `aria-label` on the host, fragments `aria-hidden` | Works on a heading | Fragments still copy, and spaces are gone unless they are re-added anyway | ARIA 1.2 prohibits naming several of the roles this gets used on, including `paragraph`, so it silently does nothing on a lede. Rejected. |
| Insert a space text node inside each word span | Fixes copy | Does not fix the glyph case at all | Half a fix. Rejected. |
| **Two layers: an intact hidden string plus an `aria-hidden` visual layer** | Reads the original string, once | Copies the visual layer, which has real space text nodes between words | **Shipped.** |

What ships, inside the host element:

```html
<h1 class="fx-split" data-fx-split="words">
  <span class="fx-split__sr">Design is the bottleneck.</span>
  <span class="fx-split__vis" aria-hidden="true">
    <span class="fx-split__clip"><span class="fx-split__inner">Design</span></span>
    <span class="fx-split__clip"><span class="fx-split__inner">is</span></span>
    ...
  </span>
</h1>
```

- `.fx-split__sr` is the original string in one text node. It is visually hidden
  with the `clip-path: inset(50%)` pattern, not `clip: rect()` and not
  `display: none`, so it stays in the accessibility tree. It is **not**
  `aria-hidden`, so it is the entire accessible name of the host.
- `.fx-split__vis` carries `aria-hidden="true"`, so not one fragment reaches
  assistive technology. It stays selectable, and word fragments are separated by
  real `' '` text nodes, so the clipboard gets `Design is the bottleneck.`
- `.fx-split__sr` carries `user-select: none`, so the hidden copy never doubles
  the text in a selection. Measured: `getComputedStyle(...).userSelect === 'none'`
  in every harness run.

Each of the two consumers reads exactly one layer. Assistive technology reads
layer 1, the clipboard reads layer 2, the eye sees layer 2. Verified through the
real accessibility tree rather than through `textContent`: Playwright's
`ariaSnapshot()` of the H1 returns a single line,

```
- heading "Describe what you want to build. Get a design you can order." [level=1]
```

and of the glyph split, `- paragraph: Checked by rules, not guesses.` No
fragment node appears in either.

In glyph mode each word is additionally wrapped in a `.fx-split__group` with
`white-space: nowrap`, so a word never wraps mid-word just because its letters
are separate boxes. Glyphs are cut with `Array.from`, which walks code points,
so a surrogate pair stays one glyph.

## 2. Idempotency

`splitWords` and `splitChars` both route through one `split(el, mode)` that
writes `data-fx-split="words" | "chars"` on the host. A call in the mode already
present returns the existing elements and touches nothing. A call in the other
mode rebuilds from `.fx-split__sr`, never from the already-split DOM, so the
markup cannot compound.

Harness probe, four calls on one element in the order words, words, chars,
words: returned counts `[4, 4, 22, 4]`, and afterwards the element holds exactly
1 `.fx-split__sr` node, exactly 1 `.fx-split__vis` node, and 4 word elements.

## 3. Reveal, and why the clip box is the observed element

`revealWords(el, opts)` splits, then hands each word to
`core/observe.ts#reveal`. No IntersectionObserver, no stagger timer and no
`will-change` bookkeeping is reimplemented here. The stagger is `reveal`'s own
per element `delay`, so each word's backstop is computed against its own delay:
duration plus that word's stagger plus 200ms, exactly spec 6.6.

Call sites, all from the spec:

```ts
revealWords(h1,   { staggerMs: 45, delayMs: 150 });   // 7.1 hero H1
revealWords(lede, { staggerMs: 18, delayMs: 550 });   // 7.1 hero lede
revealWords(h2,   { staggerMs: 40 });                 // 5.5 section title
```

**The bug this file was built around, recorded because it is not obvious.**
The first implementation observed the moving inner span. That deadlocks. The
inner is translated fully below a parent with `overflow: hidden`, and
IntersectionObserver folds ancestor overflow clipping into the intersection
rect, so the inner reports an empty rect and `isIntersecting` is never true. The
element stays armed forever.

It did not fail uniformly, which is what made it worth writing down. The clip
carries `padding-bottom: 0.18em` with an equal negative margin so descenders
have somewhere to live, and the armed transform is `translateY(115%)` of the
inner's own height. At a display size those two numbers leave a sub pixel sliver
of the inner inside the clip, enough for the observer to fire, so the hero H1
revealed correctly while the lede at 20px stayed invisible. Measured before the
fix: 18 of 66 words stuck at `opacity: 0`, every one of them in the lede.

The fix is structural: `splitWords` and `splitChars` return the **clip** boxes,
not the inners. The clip never moves and is never clipped, so it is the only
safe thing to observe, and `.is-revealed` lands on it. The inner's
`transitionend` bubbles up to the clip, which is where `core/observe.ts` has its
listener, so the opacity-only guard and the backstop both keep working
unchanged.

## 4. Why no element can sit at opacity 0 under reduced motion

Spec 19 makes this a hard gate and split text is the likeliest thing to break
it. Four independent layers, in order of which one catches it first:

1. **The settled state is the CSS default.** `.fx-split__inner` has no opacity
   and no transform of its own. Splitting text never hides it. An element that
   was split but never revealed, or that was split before script died, is fully
   visible.
2. **The hidden state needs `.fx-split--armed`,** and that class is added at
   exactly one place in `splitText.ts`, inside a branch that has already
   returned if `prefersReducedMotion()` is true. There is no second path.
3. **`.no-motion .fx-split__inner`** sits last in the block at (0,2,0) and beats
   both the armed rule and the settled rule on document order. This is the case
   the JS guard cannot catch: a user turning reduced motion on after an element
   was armed but before it was revealed. `core/motion.ts` toggles `.no-motion`
   on the live media query change, so the CSS follows immediately.
4. **The `prefers-reduced-motion: reduce` media query** repeats the armed
   selector so it matches at (0,2,0) and still wins on order. It holds even if
   no script runs at all.

`core/observe.ts` adds the fifth layer underneath: its own reduced-motion branch
applies `.is-revealed` synchronously and never creates an observer, a timer or a
`will-change` hint.

Measured: peak words at `opacity: 0` over the first 1.5 seconds under reduced
motion is **0**, in both viewports, and `will-change` is applied **0** times.
With motion on, the peak is 36 words hidden and 27 elements carrying the
hint mid flight, and both are back to 0 after the sweep. That pair of numbers is
the point: the hint is genuinely applied while the transition runs and genuinely
released afterwards, rather than never being applied at all.

## 5. counter.ts

`countUp(el, to, opts)` animates on enter over 1.2s on the `--ez-out-expo`
curve, with `font-variant-numeric: tabular-nums` so the box does not jitter.

Per spec 12.1, nothing constant is built inside the frame loop:

- the easing curve is solved once at module load into a 65 entry
  `Float64Array` sampled from `EZ.outExpo`, so it cannot drift from the
  `--ez-out-expo` token, and the loop does two array reads and one lerp instead
  of a Newton solve;
- the `Intl.NumberFormat` and the finished string are built once per counter,
  before the loop;
- the suffix is its own text node, written once, so the loop never concatenates
  and never builds a template literal;
- the loop writes `nodeValue` on one text node, and only when the rounded value
  actually changed, so an unchanged frame touches no DOM at all.

Under reduced motion the final value is written synchronously and no frame loop
is started. Measured: with reduced motion on, sampling every 50ms for 1.5s
observed exactly one value, `88`. With motion on, the same sampling observed a
run of intermediate values ending at `88`.

Nothing here sets opacity or transform, so the module cannot leave an element at
`opacity: 0`, and it correctly never adds `will-change`: there is no transition
to hint at.

**It ships unused, by design.** BUILD_CONTRACT override A6 Q3 resolves spec 20
Q3 as "no verified statistics", so section 02 ships as prose only and the stat
row is deleted. `counter.ts` is still built, correct and exported, exactly as
that override requires. It invents no number: `to` is always the caller's, there
is no default value anywhere in the file, and the only numerals that appear
anywhere in this package are harness fixtures in `qa/text-fx-harness.html`,
which is not part of the bundle.

## 6. CSS

One block at the end of `src/styles/sections.css`, opened
`/* ==== WP-08: Text FX ==== */` and closed `/* ==== /WP-08 ==== */`, per spec
18.2 and BUILD_CONTRACT C6. Every selector is prefixed `.fx-split` or
`.fx-counter`. Maximum specificity in the block is (0,2,0). No `!important`, no
`:not()` chain, no bare element selector, no token defined, no gradient, no
glow, no colored shadow.

Order inside the block is load bearing and is commented as such: armed, then
settled, then `.no-motion`, then the media query. All four sit at (0,2,0), so
each one wins over the one above it on document order alone. The settled rule is
written `.is-revealed .fx-split__inner` rather than leaning on the shared
`.is-revealed` at (0,1,0), which the armed rule would otherwise outrank.

## 9. Notes for other work packages

- `splitWords` and `splitChars` return the per word (or per glyph) **clip**
  elements. Animate the clip's `.fx-split__inner` child through a class on the
  clip, or just call `revealWords` and let it do it. Do not attach an
  IntersectionObserver to `.fx-split__inner`: it is translated out of an
  `overflow: hidden` parent while armed and will never report as intersecting.
- Do not set an initial `opacity: 0` on a host you intend to split. This package
  owns the hidden state, and any opacity written elsewhere is outside the four
  guards in section 4 above.
- `revealWords` takes the whole element and rebuilds its children, so call it
  after the element's text is final and do not keep references to nodes inside
  it across the call.
- WP-09a hero: `revealWords(h1, { staggerMs: 45, delayMs: 150 })` and
  `revealWords(lede, { staggerMs: 18, delayMs: 550 })`. Every other section:
  `revealWords(h2, { staggerMs: 40 })` on `.sec-head__title`, which WP-05 leaves
  unhidden precisely so this package owns its opacity.
- `counter.ts` has no consumer and is expected to have none. If a verified
  statistic ever arrives, `countUp(el, n)` is ready and needs no change.
